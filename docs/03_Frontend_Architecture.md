# 03. Frontend Architecture

## Overview
The frontend ecosystem consists of four React SPAs built with Vite. They share a similar underlying architecture but are tailored for specific user personas.

## Core Technologies
- **Framework**: React 19
- **Build Tool**: Vite 8
- **Styling**: Tailwind CSS v4
- **State Management**: Zustand
- **Data Fetching**: React Query (TanStack Query) & Axios
- **Form Handling**: React Hook Form with Zod validation
- **Routing**: React Router DOM

## Routing
Each application uses `react-router-dom` for client-side routing. 
Routes are heavily protected by a `ProtectedRoute` component that inspects the Zustand authentication store. If a user is not authenticated, or their role does not match the application's required role, they are redirected to the root login path or their appropriate dashboard.

## Layout System
Applications use a shared layout pattern consisting of:
- **Sidebar/Navigation**: For navigating between domain-specific modules.
- **Header**: For user profile access, notifications, and logout.
- **Main Content Area**: For dynamic route injection.

## Shared Components
Common UI elements (Buttons, Inputs, Modals) and domain-spanning components (like `UnifiedLoginPage`) are centralized. The `customer` app also heavily utilizes components from `lucide-react` for iconography and `framer-motion` for animations.

## State Management
- **Global State**: Managed by `zustand`. This includes authentication state (`authStore`), cart state, and UI toggles.
- **Server State**: Managed by `@tanstack/react-query`, providing caching, background updates, and loading states for API responses.

## API Layer
Axios instances are configured in `src/utils/axios.js` (or `src/api/axios.js`). These instances:
1. Point to the `VITE_API_URL` environment variable.
2. Automatically attach Bearer tokens.
3. Hook into `@shared/api/singleFlightRefresh` to handle token expiration seamlessly.

## Forms & Validation
Complex forms (e.g., registration, profile updates, menu item creation) utilize `react-hook-form` bound with `zod` resolvers. This ensures strict, type-safe client-side validation before payloads reach the API.

## Responsive Design
Tailwind CSS utility classes (`sm:`, `md:`, `lg:`) are used extensively to ensure interfaces respond gracefully from mobile devices up to large desktop monitors.

## PWA Implementation
The **Customer Portal** is configured as a Progressive Web App (PWA) using `vite-plugin-pwa`.
- **Service Worker**: Auto-generated by Workbox to cache static assets (`sw.js`).
- **Manifest**: `manifest.webmanifest` provides app icons, theme colors, and standalone display modes for installation on iOS and Android devices.
